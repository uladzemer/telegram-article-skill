## Что уже выяснено (не перепроверяй с нуля)

- Механизм — **Bot API Rich Messages 10.3** (24.08.2026): `RichTextButton` — кнопка внутри
  абзаца, `RichBlockButtons` — ряд кнопок. Не редактор статей, не inline keyboard.
- **Нужен обычный бот от @BotFather.** Ни Premium, ни Fragment, ни верификации.
  Fragment в API отвечает только за кастомные эмодзи на кнопках — косметика.
- Кнопки пишутся тегами в HTML, JSON руками собирать не надо:
  `<tg-button type="callback_data" data="a1">♜</tg-button>`, ряды — `<tg-button-row>`.
- Цикл: `sendRichMessage` → `callback_query` → **обязательный** `answerCallbackQuery`
  (иначе у игрока крутится прогресс-бар) → `editMessageText` с `rich_message`.
- **1–8 кнопок в ряду**, `callback_data` — 64 байта.
  Есть `type="disabled"` и `style` (`success`/`danger`/`primary`/`link`).
- Лимит ~1 действие в секунду **на чат**, `editMessageText` в него входит. Для пошаговой
  игры хватает; для аркад — нет, там нужны Mini Apps.
- **aiogram строго ≥3.31.0** — в старых версиях баг #1890: чужое сообщение с такой кнопкой
  роняет разбор обновлений и бот намертво виснет в long polling.
- Хостинг для этого демо **не нужен** — long polling с машины.
- Живой пример целиком: `github.com/DarknessShade/TeleRich`.

## Порядок: сначала доказать, потом упаковать

### Этап 1 — рабочее демо

**Крестики-нолики на Rich Messages.** Требования:

1. Поле 3×3 кнопками прямо в сообщении, каждое нажатие перерисовывает его на месте.
2. Состояние — целиком в `callback_data` (влезает в 64 байта), **без базы и без файлов**.
3. Занятые клетки — `disabled`, а не исчезают. Выигрышная линия подсвечивается стилем.
4. Определение победы и ничьей, кнопка «начать заново».
5. Простой противник-компьютер: ходит в выигрыш, блокирует, иначе центр/угол.
6. Запускается локально одной командой, только токен бота в переменной окружения.
7. Python + aiogram ≥3.31.0. Зависимости — минимум.

Отдельным файлом — короткий README: как получить токен у @BotFather, как запустить,
что проверить.

### Этап 2 — навык и репозиторий

Когда демо заработает и я подтвержу скриншотами, упаковываем в репозиторий
`telegram-interactive-skill` той же структуры, что первый:

```

references/
  rich-messages.md           — синтаксис tg-button, лимиты, версии библиотек,
                               что проверено и что нет
  choosing-the-approach.md   — Rich Messages vs Mini Apps vs Games:
                               пошаговое против аркад, где проходит граница
examples/
  tictactoe/                 — рабочий бот из этапа 1
README.md + README.ru.md     — переключатель языка, скриншоты сверху
```

Главные вещи, которые навык обязан доносить (они же — его ценность):

- механика «кнопка в тексте + перерисовка сообщения на месте» и когда она уместна;
- **граница применимости**: пошаговое — да, аркады — нет, лимит ~1 действие/сек на чат;
- обычного бота достаточно, Fragment и Premium ни при чём (частое заблуждение);
- ловушка aiogram <3.31.0, вешающая бота намертво;
- обязательный `answerCallbackQuery`.

### Этап 3 — рассказать

Объявление о навыке — тем же способом, что и о первом: страница с кнопкой копирования
под редактор статей Telegram, плюс карусель слайдов 1080×1080. В репозитории
`telegram-article-skill` есть готовые образцы: `examples/announcement.html` и
`examples/carousel/slides.html` — бери их за основу, структура уже отработана.

Демонстрацию записать: короткая запись экрана или серия скриншотов, где видно, как
нажатие меняет сообщение. Статичная картинка этого не передаёт — а именно это и надо
показать.

## Порядок работы

1. Сначала **сверься с актуальной документацией** `core.telegram.org/bots/api` по
   `sendRichMessage` и `InputRichMessage` — разведке уже несколько дней, а API свежий.
   Если синтаксис разошёлся с тем, что записано в памяти — верь документации и скажи мне.
2. Покажи план, прежде чем писать код.
3. Пиши в **новую папку `D:\github\telegram-interactive-skill`**, не в существующие
   репозитории.
4. Токен я дам, когда попросишь, — сам его никуда не вписывай и не коммить.
5. Репозиторий создавать только по моей команде, когда демо проверено.
